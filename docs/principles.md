# 設計原則

## 製品

- PRINCIPLE-001: 製品名は `HatoNote` とする。
- PRINCIPLE-002: Windows上でMarkdown文書を閲覧、編集、管理するデスクトップアプリとする。
- PRINCIPLE-003: 単一Markdown、MDZ、mdBook形式のMDZ、スライド形式のMDZを扱う。
- PRINCIPLE-004: 既存の `.mdz` 拡張子とMDZip互換の考え方は継承する。
- PRINCIPLE-005: 機能を増やすこと自体を目的とせず、文書閲覧と編集に直接必要な機能を優先する。

## UI

- PRINCIPLE-010: 同じ意味の操作は文書種別が異なっても同じ操作体系を使用する。
- PRINCIPLE-011: 表示状態、編集エンジン、未保存状態、現在位置、Undo可否をUIから判別できるようにする。
- PRINCIPLE-012: ページ移動や表示状態変更だけで画面全体を不要に再読み込みしない。
- PRINCIPLE-013: ページ移動や表示状態変更で、維持可能なスクロール位置や選択状態を不必要に失わない。
- PRINCIPLE-014: WebViewの既定動作よりHatoNoteの操作仕様を優先する。
- PRINCIPLE-015: プレビューは不具合やはみ出しを隠すために内容を切り捨てない。
- PRINCIPLE-016: 状態切替には、現在状態を視覚的に判別できるUIを使用する。
- PRINCIPLE-017: 同じ種類の状態切替は同じ見た目と操作体系を使用する。

## 設計

- PRINCIPLE-020: 文書種別、表示状態、編集エンジン、画面を別々の概念として扱う。
- PRINCIPLE-021: 新しい文書種別を追加するとき、既存の表示状態や編集エンジンを再利用できる設計とする。
- PRINCIPLE-022: 新しい表示状態を追加するとき、既存の文書種別を個別判定する実装をアプリ全体へ増殖させない。
- PRINCIPLE-023: 文書種別ごとの差異は能力として定義する。
- PRINCIPLE-024: 画面固有の条件と画面横断機能の条件を分離する。
- PRINCIPLE-025: 既存の機能を移植するときも、HatoNoteの仕様書を正とする。

## データ

- PRINCIPLE-030: 保存失敗によって既存の保存済み文書を破損させない。
- PRINCIPLE-031: 文書外部の変更を検出できる場合は、無条件に上書きしない。
- PRINCIPLE-032: 未保存変更の有無を明示的に管理する。
- PRINCIPLE-033: ユーザーが破棄を選択しない限り、未保存の編集内容を意図せず失わない。
